# buildcalc — контекст для нового диалога

Вкладка «Калькулятор» в профиле героя (Farever, hlx-runtime). Подбирает лучший билд: вещи, оружие, арсенал,
пропитки, таланты (с финальным талантом и печатью в шлеме), умения и руны. Сначала прочитать
`C:\mods\teleport\README.md` (общие правила и окружение). Подробности старой эвристической модели — `DESIGN.md`.

## Требования пользователя (жёстко)

- Ответы только по-русски. Без коммита/пуша без команды. `dist` не в git. `buildcalc/` пока не в git.
- Никакого хардкода, всё из данных игры, для любого класса. Не гадать: проверять код игры (`q.py dis`) и данные.
- Не подгонять результаты под желаемые цифры. Полное логирование (`hlx/buildcalc-debug.txt`).
- Сравнивать вещи по характеристикам, не по редкости. Никаких бесполезных статов (физ. пробой жрецу).
- Арсенал даёт 40% статов (показывать так), 2 навыка арсенала (`Weapon.isValidArsenalSkill`).
- Пропитки: только наборы ≥ 2 вещей, не больше 8 пропитанных; в окне — «Цепное исцеление — 4 предмета»,
  на вещи — значок пропитки в углу; рекомендованная пропитка должна быть видна в подсказке вещи.
- Игра не должна подвисать (слабые ПК!), расчёт до ~20 с. Игроку не нужно проводить бой/стоять у манекена.
- Алгоритм (одобрен): эмулировать текущий билд → запомнить → эмулировать варианты → лучший сравнивать
  с текущим → вывести лучший. Оси: урон по манекену, лечение себя, броня/защита (характеристика),
  здоровье (характеристика). Камни/свитки зачарования не перебирать.
- Удалено по требованию: строки «Урон %/Лечение %», блок «Почему эти замены» (ломал интерфейс).

## Как устроено сейчас

- `sim/` — свой симулятор боя, независим от игры: `Script.hx` (парсер hscript, все 508 скриптов),
  `Interp.hx` (интерпретатор), `SimData.hx` (данные навыка), `Sim.hx` (события, ротация, статусы,
  зоны с `detectPresence`, призывы, молитвы жреца `PriestObj`, `chainStep` как в игре, удары по герою
  1 урон/с, дебаффы цели, журнал ударов + `replay`).
- `GameEnv.hx` — данные игры для симулятора: статы через `StatEngine`, сила предмета
  `HSkill.getStepEffectItemScaling`, защита цели.
- `Model.evaluate` = статы + бой 60 с (`simulateInto`). Кэш боёв по набору навыков; если меняются только
  статы, не влияющие на ход боя (не CDR/каст), — пересчёт журнала (`replay`, ~1 мс вместо ~30 мс).
- `Optimizer` — поиск в фоновом потоке (10 мс работы / 5 мс сна), `G` с мьютексом, `DebugLog` с мьютексом.
  Оценка = Σ вес × (значение / значение текущего билда). Проходы: вещи, пропитки, таланты
  (варианты «с нуля» + локальный перенос очков), умения/руны.
- В конце: самопроверка эффектов против `HSkill.getStepEffectScaling` (все совпадали), строки
  `compare slot` (новая vs надетая, без пропитки, разница статов).
- Тест офлайн: `cd C:\mods\buildcalc && haxe -cp src -cp simtest -main SimTest --interp`
  (data.cdb в `...\65421b85-...\scratchpad\data\data.cdb`). Сборка: `haxe compile.hxml`,
  архив `C:\mods\dist\buildcalc.zip` (`hlx/mods/buildcalc/buildcalc.hl`).

## Проверенные факты игры

- Урон: `(1 + Mastery + Fervor) × DamageModifier`; Fervor входит в `HealGivenMultiplier`.
- Снижение: броня × (1 − игнор) × (1 − пробивание) / (… + F0 + F1 × уровень **атакующего**)
  (`GameObject.getAffinityDamageReduction`). Броня манекена = `getResistanceLevelScaling(атрибут,
  уровень манекена, 0.4)`; уровень манекена задан на карте → читать у настоящего манекена
  (мод сохраняет замер в `state.json`, поле `dummy`); без замера — ожидаемая броня игры.
- Статус шага без `target` вешается на цель шага, `Self` (0) — на себя (`SkillStep.applyStatus`).
- `chainStep`: главная цель сразу, далее только другие союзники (владелец исключён).
- Fervor: 1 рейтинг ≈ 0,053% при ур. 25. Для жреца 1% Fervor ≈ 1,5 Веры по урону.

## Сверка с измерителем урона (2026-10-17)

Реальные бои у манекена пишет мод dps-meter (xWink): `D:\Steam\steamapps\common\Farever\hlx\mods\dps-meter\history\Target dummy\`
(`fight_*.json` — по умениям, `*.json.timeline` — построчный JSON: заголовок + каждое событие с временем, суммой, критом,
целью). `SimTest` печатает строки `hit <умение>: удары, средний удар без крита, dmgMult` для сравнения.

Найдено и исправлено (всё по коду игры):
- Цепочка атак: `Hero.getNextAttackSkill` — каждая атака оружия (`hero.attackSkills`, типы Attack…Attack4) по разу,
  затем AttackCombo; `moveSet.comboLength` не участвует. Скипетр: атака → комбо (было 3 атаки + комбо).
- Область с `ignoreMainTarget`, сыгранная скриптом на цель (`playStep(AreaDamage, ctx.aimTarget)`), — центр области,
  саму цель не бьёт (Sunlight AreaDamage −50% бил манекен).
- Статусы складываются как `Status.stacksWith`: тот же статус, тот же наложивший (флаг 2048 — общий для всех),
  оба бесконечные или оба конечные. Шаг-статус передаёт свою длительность (огонёк S2 на 8 с отдельно от вечного).
- Повторяющийся шаг бесконечного статуса тикает до конца боя (лечение огонька тикало 1 раз).
- Попадание области без урона/лечения (только статус) — тоже попадание: `SkillStep` → `BaseSkill.onHit` →
  `onInflictHit` (так S2 и щит Skill1 держат Sunlight).
- `hit.isSkill` = навык оружия (WeaponSkill, WeaponSubSkill), ClassSkill или «сигнатурный» (`HSkill.isSignature`:
  SignatureSkill, RoguePoison, PriestPrayer, MageConduit, Mage_SparkMaster, Rogue_MasterPoisoner); `isActiveSkill` =
  WeaponSkill/ClassSkill/SignatureSkill; `hit.isFinalCombo` = тип AttackCombo. (Раньше isSkill был любой тип из ACTIVE.)

Почему калькулятор предлагал плохие таланты (`simtest/TalentTest.hx`, аргумент `real`): модель применяет ВСЕ классовые
умения по откату. Faithful Winds (без урона) 10 с из 15 бьёт героя областью каждые 0,5 с и держит Sunlight → Solar Devotion
стоит 7 DPS. В реальном бою игрок Faithful Winds / Radiant Verdict / Beacon не применял: тогда Solar Devotion = 80 DPS,
текущие таланты 570 DPS против предложенных 519 (реальный DPS по одной цели ≈ 559). Без этих умений DPS выше — их
применение отнимает время атак. РЕШЕНИЕ ПОЛЬЗОВАТЕЛЯ: модель применяет ВСЕ умения (не менять);
  объяснять игроку, что рекомендации рассчитаны на применение всех умений.
- Попадание (`onHit`/`onInflictHit`) — как в игре: один раз на цель за касание шагом (`SkillStep.doApply` → `hitEntity`:
  EffectTarget, SelfEffect, Channel; области; ауры) и за попадание снаряда (`Projectile.onHit`), а не за каждый эффект.
  Lifestealing (50% на попадание с Combo): 2 попадания на Combo, как в логе.
- Печать (аугмент-талант) выбиралась по талантам момента выбора (кэш `bestAugs` без талантов) → Luminous Bastion
  (ценность 0: `onGameBeat` не моделируется). Кэш теперь с ключом талантов, проход по вещам переподбирает аугменты.
- Арсенал: у ячейки — родная подсказка игры; доля 40% и навыки арсенала — подсказка подписи «Арсенал ×0.4».
- `playAreaStepFromPt` (бомбочки Kobold DPS) — область в точке цели через `area.travelTime` (раньше не считалась).
- Узел дерева с печатью показывает и изменение очков («печать 1→0»).
- Офлайн `TalentTest stat`: +4 Веры ≈ +2,0% урона/+2,1% лечения, +13 рейтинга Рвения ≈ +0,5%/+0,7%.
- Кнопка «Рассчитать» во время расчёта без процента (процент — в строке состояния).
- Проверка предложенных талантов в бою 16:19 (dps-meter): 583 против 596. Причина: калькулятор снял очко с Solar Devotion,
  рассчитывая на печать Solar Devotion в новом шлеме; игрок поставил только таланты → Sunlight снимался 17 раз,
  27,4 → 20,4 срабатываний/мин. Рекомендация талантов зависит от печати, которой у игрока нет.
- Пропитки: пороги 2/4/6 вещей (`Const.Items.Item_InfusionCaps`) → ранги 1/2/3. Ultimate ранга 3 (Manfish) —
  умение без отката, включаемое скриптом (`checkEnabled`, слот сигнатурного через `skillOverride`): модель его не
  применяла никогда (голые `Ok`/`Invalid` в скрипте разрешались в объект имён, не в строку). Исправлено: `Names.of`,
  такие умения в `actives`; умение без длительности в данных — мгновенное (0,02 с; в логе игры 0,014 с).
- Офлайн-тест: `AllAttributes` = среднее атрибутов с флагом 8192 (Str/Dex/Faith/Int), раньше = Вера (завышал в 2,4 раза).
  `TalentTest inf`: Manfish×6 567 DPS, Manfish×6+Crimson×2 599, Crimson×4+Manfish×4 601.
- Печати (аугменты-таланты) не меняются: новая вещь получает печать героя из этого слота (решение после боя 16:19).
- Faithful Winds в боях с боссами обновляет Sunlight ~11 раз за 10 с (модель ~20: герой всё время в ветре).
- Лог: строки `why talent …` и `why infusions …` — вклад каждого изменения (вернуть только его к текущему).

Итог теста (жрец, ранг навыков скипетра 3): 392 → 510 DPS; Combo 146/с (игра 149), Sunlight 100 (102),
Skill1 64 (74), атака 17 (19). Реальный DPS по одной цели ≈ 559: Smite в логе бьёт 4 манекена (радиус 20 м).
Навыки кадила в тесте ниже игры в 1,4 раза — тест не знает силы предмета (`getStepEffectItemScaling`), мод знает.

## Все классы (2026-10-17)

Проверка: `haxe -cp src -cp simtest --run AllClassTest` — 4 класса × всё оружие игры × все пропитки, список того,

- Маг (`MageComponent`): Искра за навыки оружия и Combo (`Skill.getSparkCost`: Combo — `Mage_Spark_SpellCDCost_FinalCombo`,

- Глобальные шаги (`stepGlobal.globalId`), объекты-подборы (`SkillObject` → шаги Pickup), `stopAreas`, `cancelWaits`, ~40 функций.
- Дистанция до манекена = дальность первой атаки оружия (ближний бой — 2–3 м, дальний — дальность выстрела).

## Гибрид (2026-10-17, решение пользователя)

- Вещи без своих навыков (броня, кольца, ожерелье, плащ; слоты > 1, `skills` пусто, без аугментов-навыков) оцениваются
  по характеристикам: `Model.statsOnly` — пересчёт (replay) уже проведённого боя тех же навыков, даже если сменился
  атрибут хода боя (крит, откаты); новых боёв нет. Так в `ItemPass` и `Prefilter` (`Optimizer.statsOnlyItem`).
- Боем: оружие, арсенал, тринкеты/вещи с навыками, пропитки (InfusionPass — всегда полный бой), таланты, умения;
  итоговый билд — полный бой.
